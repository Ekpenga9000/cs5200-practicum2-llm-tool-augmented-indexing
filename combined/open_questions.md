# Open Questions and Data Caveats

- JOB is not analyzable as a three-condition benchmark. `results/sylfhen/JOB/condition_b_results.csv` is missing on both `louis`/`main` and `origin/sylfhen-condition-a`. Baseline and Condition A have 113 aligned query IDs, but no B values exist.
- The seven included triplets have populated, numeric timing columns and matching query ID sets. Some non-timing fields contain nulls or timeout/error text, so calculations use only the timing columns and do not treat metadata as a measurement.
- Timeout policy is not represented as a dedicated column in these CSVs. The repository contains timeout/error handling in runner code and result metadata, but the historical outputs do not provide one uniform, machine-readable timeout policy for every benchmark. Exact cross-benchmark timeout comparability therefore remains uncertain.
- Git history provides useful chronology but not proof of identical database snapshots. TPC-DS baseline and Condition B were corrected together in commit `dcb29e6`; STATS baseline/A/B were remeasured together in `800e922`. Older TPC-H, TPC-C, TATP, SSB, and DSB files were committed in separate benchmark-specific runs, so snapshot equivalence is not independently established here.
- The aggregate uses the arithmetic mean of per-query execution times. This is a judgment call because the result files do not consistently document whether timing values are single runs, medians, or repeated-run summaries. The STATS summary explicitly describes clean median-of-7 remeasurement; other benchmarks may use different protocols.
- The chart contains seven bars, not eight, because assigning a Tool Benefit to JOB would require inventing missing Condition B data.
- SSB has no single dominant baseline outlier: its baseline range is 2766.376-6783.610 ms, and B regresses on 8/13 queries. Its negative aggregate B result is therefore not explained only by one suspiciously tiny or huge baseline value.
- DSB is outlier-sensitive. Baseline Q37 is 359092.554 ms and Q48 is 69698.8 ms; excluding those two baseline-largest queries changes the baseline/A/B means from 9742.138/8438.581/10110.858 ms to 1716.510/377.039/665.051 ms. B still trails A, but the full-workload mean is materially shaped by these queries. B improves 42/53 queries and regresses 11/53, so the negative mean is driven by a smaller set of large regressions.
- TPC-C is also outlier-sensitive: Q12 is 197.992 ms while the other 11 baseline queries are at most 0.252 ms. The summary documents standard one-warehouse scale and median-of-7 runs after warm-up on freshly reset databases, so the near-zero point-lookups are plausible for this small OLTP workload rather than the TPC-DS stale-baseline signature. However, the measured result files date to Aug 4, while the current canonical schema/workload files were added Aug 15; exact input identity cannot be proven from Git. Treat the -2.206 pp B-vs-A result as low-confidence and do not headline it as evidence that tool access hurt performance.
- Across complete schemas, strict per-query counts (improved / regressed / tied versus baseline) are: TPC-H A 11/11/0, B 19/3/0; TPC-DS A 74/22/3, B 65/31/3; STATS A 57/89/0, B 52/94/0; TPC-C A 6/3/3, B 6/3/3; TATP A 9/2/1, B 10/2/0; SSB A 11/2/0, B 5/8/0; DSB A 49/4/0, B 42/11/0. These counts should accompany the arithmetic means because means can be dominated by one or two expensive queries.
- TATP provenance confidence: **high for result/input identity and file-set chronology, medium for exact runtime cache-state equivalence**. Baseline, A, and B were committed together in `b51e97b` on Aug 10, using the original `tatp_schema.sql` and `tatp_workload.csv`. The later canonical `schema.sql` and `workload.csv` added in `030da4b` are byte-identical to those original inputs. The TATP summary documents median-of-7 `EXPLAIN ANALYZE` runs after one warm-up on a freshly reset PK/FK-only database before each condition. No TATP-specific cache warning or JOB-style stale-baseline caveat was found, but Git and the CSVs cannot prove OS/page-cache state; classify the positive aggregate as **medium-confidence**, rather than treating cache equivalence as proven.
- TATP's positive mean is partly outlier-sensitive but not dependent on a single anomalous result. Baseline mean/median are 17.483/4.608 ms; Q12, Q10, and Q11 are the largest signal queries at 47.117, 46.281, and 44.121 ms. The two largest baseline queries (Q12 and Q10) account for 44.5% of baseline total time. Removing them changes baseline/A/B means from 17.483/11.689/10.890 ms to 11.639/4.862/4.568 ms, reducing Tool Benefit from 4.569 pp to approximately 2.54 pp while preserving its positive direction. B improves 10/12 queries, regresses 2/12, and ties none; the two regressions are low-cost queries, so the positive result is supported by both the count and the signal-bearing queries, with reduced effect size after outlier removal.
- STATS provenance confidence: **high for same-session/file-set chronology, medium for exact runtime cache-state equivalence**. `baseline_results.csv`, `condition_a_results.csv`, and `condition_b_results.csv` were all replaced together in commit `800e922` on Aug 21, whose message identifies a clean, median-of-7 remeasurement. The STATS schema and workload were canonicalized earlier in `030da4b` on Aug 15, so the result files postdate the current inputs. This is materially stronger provenance than TPC-C's result files, which predate its current canonical schema/workload.
- No STATS-specific evidence of the JOB warning was found. JOB has an explicit baseline-validity caveat and a separate clean-database correction in its history; STATS's latest commit explicitly describes a clean remeasurement and replaces baseline/A/B together. However, Git history cannot prove OS/page-cache state, and the CSVs do not record cache warm/cold status or a machine-readable timeout policy. Do not call STATS cache equivalence proven; classify the aggregate as **medium-confidence**, not a confirmed stale-baseline artifact.
- STATS is strongly outlier-sensitive. Baseline mean/median are 27176.417/224.516 ms; s120 is 1207053.123 ms, s122 is 1130644.914 ms, and s58 is 883909.657 ms. Removing only the two largest baseline queries changes baseline/A/B means from 27176.417/20428.836/27166.821 ms to 11319.853/11509.764/10994.986 ms. The full mean says B is 24.794 percentage points worse than A, but B improves 52/146 queries and regresses 94/146; the result is therefore driven by a small number of high-cost regressions rather than a majority of queries. The median tells a different story: B's 217.856 ms is below A's 256.728 ms and close to baseline's 224.516 ms.
